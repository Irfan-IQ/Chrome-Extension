1. Glossary of Technical Terms

A simple reference guide explaining the parameters measured in this benchmark.

CPU Utilization (%)

How much computation capacity the computer processor is using. We record Baseline (Before), Average During the Task, Peak Surge, and After Completion.

RAM PSS (Proportional Set Size)

The fairest real-world measure of RAM. It includes the memory used only by this task, plus its fair share of shared operating system libraries.

RAM Private

Memory dedicated exclusively to this application that cannot be shared with any other background app.

Delta Peak PSS (Δ PSS)

Calculated as Peak RAM - Baseline RAM. It tells us how much extra memory the program demanded while working at full speed.

Memory Leak (PSS MiB)

Calculated as After RAM - Before RAM. If positive and large, the app forgot to release memory when done. If near zero, cleanup was successful.

MiB (Mebibyte)

A standard unit of computer memory (1 MiB = 1,024 KiB = 1,048,576 bytes), roughly equivalent to one Megabyte (MB).

7. Summary: What Is This All About? (In Simple Terms)

A quick, jargon-free overview of the experiment, its purpose, and the final conclusion.

🔬

1. What Did We Test?

Imagine running a heavy program—like opening a demanding webpage or launching a script—30 consecutive times. We monitored the computer like a medical heart-rate monitor, checking how hard the processor worked and how much memory was used before, during, and after each run.

⚡

2. What Happened During The Runs?

When the program started, the computer briefly spiked its CPU from an idle ~3% up to an average peak of ~22% (and at most 47%). At the same time, it asked for roughly 352 MiB of extra temporary memory workspace. Once the task finished, processor usage dropped back to normal almost immediately.

🛡️

3. Did The Program "Leak" Any Memory?

A memory leak happens when an app borrows memory from the computer but forgets to return it when finished, eventually causing the system to slow down and crash. Here, the net retained memory after closing averaged only +0.39 MiB—less than half a photo file. That tiny variation is just standard system background noise, confirming no memory leak exists.

✅

4. Final Verdict

The application is stable, resource-friendly, and safe for continuous execution. To run this system smoothly in production or inside a cloud container, provide a comfortable buffer of at least 500 MiB of available RAM above baseline idle.
