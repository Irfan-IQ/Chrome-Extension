1. Summary

A quick look at what happened during the test and what the results mean.

What Did We Test?

Imagine running a heavy program—like opening a demanding webpage or launching a large app—30 times in a row. We watched the computer closely like a health monitor, checking how hard the processor worked and how much memory was used before, during, and after each run.

What Happened During The Runs?

When the program started running, the processor briefly spiked its workload from an idle ~3% up to an average peak of ~22% (and at most 47%). At the same time, it asked for roughly 352 MiB of extra temporary memory space to get the job done. Once finished, processor usage dropped right back to normal.

Did It Leave Any Memory Behind?

A memory leak is when an app borrows memory from the computer but forgets to give it back when done, eventually slowing everything down. Here, the memory left behind averaged only +0.39 MiB—less than half a smartphone photo. That tiny difference is just normal background noise, proving no memory leak exists.

2. Glossary of Technical Terms

Simple explanations for the computer terms used on this page.

CPU Utilization (%)

How much brainpower the computer's processor is using at any given second. We record Resting Idle (Before), Average Work, Peak Surge, and After Finishing.

RAM PSS (Proportional Set Size)

The fairest real-world measure of memory. It includes the memory used only by this task, plus its fair share of common system files it shares with other apps.

RAM Private

Memory reserved strictly for this one program that cannot be touched or shared with any other background software.

Delta Peak PSS (Δ PSS)

Calculated as Peak RAM - Starting RAM. It tells us how much extra temporary memory room the program requested while working hard.

Memory Leak (PSS MiB)

Calculated as Finished RAM - Starting RAM. If positive and large, the app forgot to give memory back. If close to zero, cleanup was successful.

MiB (Mebibyte)

A standard unit of computer memory (1 MiB = 1,024 KiB), very similar to one Megabyte (MB).

5. Extra Memory Room Needed (Δ Peak PSS)

How much additional temporary memory the program asked for while working.

How to Read This Graph
  • Each bar shows how much extra memory was needed (Peak RAM minus Starting RAM).

  • Taller bars (like Trial 29 at 487 MiB) mean that specific run handled a slightly heavier task.
Key Observations

Most tasks temporarily need an extra 300 to 400 MiB of working room. Giving the computer an extra 500 MiB of free room ensures the app will always run without crashing.

How to Read This Graph

Across all 30 runs, the net difference was only +0.39 MiB—virtually zero. Because the numbers stay very close to the zero line and don't grow over time, the app cleans up properly and has no memory leaks.
